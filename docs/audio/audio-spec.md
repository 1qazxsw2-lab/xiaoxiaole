## 0. 阅读依据与现状摘要（已核实）

来源文件：`assets/scripts/audio/AudioManager.ts`、`tools/gen_audio.py`、`assets/audio/*.wav`。

**`AudioManager.ts` 现状**
- `AudioEvent` 枚举共 7 个，值为字符串键：`select` / `swap` / `match` / `big_match` / `invalid` / `shuffle` / `music_bg`。

- `PlayOptions` 含 `rate` 字段，但 `play()` 内第 100 行 `src.playbackRate = ...` **已被注释** → 当前运行时**无任何音高变速**。

## 1. 关键约束：Cocos Creator 3.x 的 `AudioSource` 没有 `playbackRate` / `pitch`

Cocos Creator 3.x 的 `AudioSource` 组件**不暴露播放速率或音高属性**（iOS/Web/native 一致）。因此：

- ❌ **不能**用运行时调速（如 `playbackRate = 1.05`）做连锁升调 —— 即便把第 100 行取消注释，3.x 也无该属性可赋值。
- ✅ **方案 A（主推，跨平台零风险）**：为连锁各档**预渲染不同音高的独立音频文件**（如 `match_0`…`match_5` 按半音升调）。播放时按 combo 档位选文件，完全不依赖运行时调速。
- ◑ **方案 B（可选，仅 Web/H5）**：绕过 Cocos，直接用浏览器 `AudioContext` 对单一 `match` 采样做 `detune`/`playbackRate` 调速，音高可连续平滑。代价：需自建一层音频调度、要处理 iOS 自动播放策略与和 Cocos 总线的混音一致性，**仅 H5 可用**，不推荐作为主方案。

> 本规格书以**方案 A** 为交付基准；方案 B 仅在 §4 末尾作为可选增强说明，不纳入本次资产清单。

## 3. 逐事件规格

### 3.1 SELECT（选中方块，第一次点击）
- **音色描述**：极短、干净的高音木琴/电子 click（正弦或轻三角波），带 < 3ms attack、几乎无尾音；听感「轻盈、确定」。
- **时长**：0.06–0.10s。
- **情绪/反馈意图**：确认「我选中了这个方块」，中性偏正，不打断节奏。
- **音量优先级**：P2；峰值 0.50（−6.0 dB）。点击频繁，不宜过响以免疲劳。

### 3.2 SWAP（交换动作，第二次相邻点击）
- **音色描述**：两个极短脉冲（木质/电子 tick），第二音比第一音高约 +3~+5 半音，模拟「咔—嗒」位移感；可加极轻噪声起音增加「实体感」。
- **时长**：双音合计 0.14–0.20s（第二音延后 ~75ms）。
- **情绪/反馈意图**：表达「两块正在交换」，制造期待，引导玩家等待消除结果。
- **音量优先级**：P2；峰值 0.55（−5.2 dB）。

### 3.3 MATCH（普通消除 / 连锁档 0）
- **音色描述**：明亮上滑「啵」/水滴感（正弦 + 轻二次泛音），音高自高向低小滑（如 880→660），带轻微「噗」气声收尾；听感「愉悦、奖励」。
- **时长**：0.12–0.18s。
- **情绪/反馈意图**：消除成功的**核心正反馈**，每次消除都给「爽」的一下。
- **音量优先级**：P2；峰值 0.60（−4.4 dB）。连锁档 1–5 用同名变体（见 §4），增益保持一致。
- 注：`match` 本身即连锁第 1 档（combo=1）的基础音；更高档由 `match_1`…`match_5` 升调体现。

### 3.4 BIG_MATCH（大连消 / 大量方块消除）
- **音色描述**：辉煌上行琶音（建议四音，如 C–E–G–C 或五音），三角波/加法合成，叠加一层柔和亮垫增强「成就爆棚」感；比 `match` 明显更长更满。
- **时长**：0.45–0.60s（琶音各音约 0.12–0.16s，依次延后）。
- **情绪/反馈意图**：大消除的**高光奖励**，区别于普通连锁的逐档升调；由「单次消除方块数阈值」触发（沿用现有 `big_match` 语义）。
- **音量优先级**：P2；峰值 0.72（−2.9 dB）—— 全 SFX 中最响，突出奖励但不掩 UI 关键音。

### 3.5 INVALID（无法消除，回弹）
- **音色描述**：低沉下行音（方波/锯齿 + 轻微拍频不和谐），如 220→150Hz 下滑，带闷感；**刻意「挫败」但绝不能刺耳**。
- **时长**：0.20–0.30s。
- **情绪/反馈意图**：明确告知「这一步无效、方块弹回」，是**最重要的负反馈**——玩家必须立刻听出来。
- **音量优先级**：**P1（最高）**，峰值 0.60（−4.4 dB）。在任何混音竞争下都不应被掩盖或回收。

### 3.6 SHUFFLE（死局重开 / 洗牌）
- **音色描述**：带通扫频的白噪声 whoosh（低通平滑），空气感、无明确音高；可叠极轻的「卡片翻动」质感。
- **时长**：0.45–0.60s（噪声钟形包络，中段最强）。
- **情绪/反馈意图**：提示「盘面正在重排」，过渡性音，不抢戏。
- **音量优先级**：P3；峰值 0.50（−6.0 dB）。

### 3.7 MUSIC_BG（背景循环乐）
- 详见 §5。

### 混音优先级说明
- **P1（关键，永不被回收/掩蔽）**：INVALID —— 失败反馈不可丢失。
- **P2（默认）**：SELECT / SWAP / MATCH(+变体) / BIG_MATCH —— 正常游戏反馈。
- **P3（可让位）**：SHUFFLE / MUSIC_BG —— 过渡与铺底，竞争时先让。
- 当前 `AudioManager` 声音池「回收最旧」无优先级；生产建议改为**按优先级回收**（详见 §8），否则 P1 在满池时可能被误回收。

## 4. 连锁（Combo / Cascade）音高映射方案（不依赖 playbackRate）

**核心思路**：连锁第 N 次消除播放 `match_{N-1}`，文件在制作阶段就已分别升好调，运行时只是「选文件」，绝不做运行时调速。

### 4.1 档位与音高步进（主推）
| 连锁档（combo 步数） | 交付文件 | 相对 `match` 的移调 | 附加处理 |
| --- | --- | --- | --- |
| 1 | `match` | 0 半音（基准） | — |
| 2 | `match_1` | +1 半音 | — |
| 3 | `match_2` | +2 半音 | — |
| 4 | `match_3` | +3 半音 | 叠一层高频「闪光」亮音 |
| 5 | `match_4` | +4 半音 | 叠高频「闪光」亮音 |
| ≥6 | `match_5` | +5 半音（封顶） | 封顶；可追加 `bigMatch` 余韵层 |

- **档位数**：6 档（0–5）。
- **音高步进**：每档 **+1 半音**（音乐性、听感平滑）。
- **封顶 +5 半音**：避免高 combo 变「唐老鸭」；combo≥6 不再升调，改靠亮度层与 `bigMatch` 余韵维持兴奋。
- 时长各档保持一致（0.12–0.18s），仅音高/亮度不同，保证连锁「连珠」节奏稳定。

### 4.2 轻量备选（档位更少）
若想压制作量：4 档、每档 +2 半音（`match` / `match_1`[+2] / `match_2`[+4] / `match_3`[+6 封顶]）。听感稍跳，但文件减半。

### 4.3 如何接入（需极小的代码扩展，非本次交付）
- 现有 `clipMap` 仅绑定单个 `matchClip`，无 combo 选档逻辑。要启用连锁升调，需由程基岩在 `AudioManager` 增加「combo 步数 → 片段」的小型查表（或新增 `AudioEvent.MATCH_COMBO` 并传入步数）。本规格书**只定义资产与命名**，代码改动不在本次范围。
- **零代码降级路径**：若暂不接 combo 选档，直接把 `match.wav` 替换为高品质基准音即可，行为与现状一致（无升调），后续再补 `match_1`…`match_5` 并接表。

### 4.4 可选增强（仅 Web/H5，方案 B）
用浏览器 `AudioContext` 对单个 `match` 采样做 `detune` 连续调速，音高更顺滑；需自建音频层、处理 iOS 自动播放与混音一致性，**不作为主交付**，仅记录供评估。

## 5. BGM 规格

- **风格**：轻松、休闲、明亮大调；轻合成器 pad 铺底 + 拨弦/木琴琶音；情绪「愉悦不焦躁」，契合三消。
- **和声走向**：沿用占位音的 **I–V–vi–IV（C 大调）** 循环，安全耐听、无强烈终止感，适合无限循环。
- **时长**：**12–30s** 循环（占位仅 8s，循环感偏重；建议拉长到 16–24s 降低疲劳）。若保持 8s 亦可，但需确保头尾无缝。
- **循环方式**：**无缝循环（seamless loop）**——尾音淡出与开头淡入对齐，或做 crossfade 头尾各 50–100ms；Cocos 侧 `musicSource.loop = true` 已支持，关键是素材本身头尾相位/能量连续。
- **配器分层（可选）**：主旋律 + 低音 pad + 轻打击（shaker/轻鼓点）三层，便于日后做「探索/连击」动态混音（本版先交单层循环即可）。
- **音量**：相对主音量 **0.40（−8.0 dB）**，恒低于所有 SFX（对齐代码 `musicVolume` 当前 0.5，建议下调到 0.4）。BGM 在任何 SFX 响起时都不应盖过反馈音。
- **格式**：MP3，44100Hz 单声道，96–128 kbps。

## 6. 体积预算

试玩广告（H5）整包常受限，音频建议 **硬上限 < 1.0 MB，舒适 < 1.5 MB，绝对不超过 2 MB**。

**测算（MP3 编码后）**
| 类别 | 文件 | 码率/时长 | 估算体积 |
| --- | --- | --- | --- |
| 基础 SFX | select/swap/match/invalid/shuffle | 64kbps，均 ~0.2s | ≈ 4–6 KB/个，合计 ≈ 25 KB |
| 奖励 SFX | bigMatch | 96kbps，0.5s | ≈ 6 KB |
| 连锁变体 | match_1…match_5（5 个） | 64kbps，~0.15s | ≈ 1.2 KB/个，合计 ≈ 6 KB |
| BGM | bg | 96kbps，16–24s | ≈ 190–290 KB |
| **合计（推荐配置）** | | | **≈ 230–330 KB** |
| 高质量配置 | BGM 128kbps + SFX 96–128kbps | | ≈ 400–600 KB |
| 占位现状（WAV 未压缩） | 7 个 WAV | | ≈ 834 KB |

> 转 MP3 后体积约为占位 WAV 的 **1/3～1/4**，留足余量。若整包预算极紧（如 < 4MB），BGM 可降到 22050Hz/64–80kbps（≈ 130–190 KB），听感损失可接受。

**预算红线**：音频总包 **< 1.0 MB**；单文件 BGM **< 300 KB**。超出即优先压缩 BGM 码率 / 缩短循环。

## 8. 实现 / 引擎侧提示（供程基岩，非本次改动）

> 以下为落地建议，本文档不修改任何代码。

1. **格式与导入**：Web 目标用 MP3（Safari 不支持 OGG）；Cocos 导入时 SFX 设 **Web Audio** 模式（低延迟、可调度），BGM 亦可用 Web Audio 但注意常驻内存。
2. **采样率**：SFX 22050–32000Hz 单声道足够；BGM 44100Hz 单声道。
3. **声音池回收策略**：当前「回收最旧」无优先级，建议改为**优先级回收**（P1 永不被回收），避免 INVALID 在满池丢失。
4. **连锁选档**：启用 §4 时，需在 `AudioManager` 增加 combo→片段查表（或新增 `MATCH_COMBO` 事件传步数）；`play()` 的 `rate` 字段维持注释（3.x 无 playbackRate）。
5. **iOS 自动播放**：H5 首声需用户手势触发，`startMusic()` 与首次 SFX 应在首次点击后启动（现有 `onLoad` 建源、点击后播放的逻辑已大体符合）。

## 9. 待主理人审批 / 待办

1. **BGM 来源**：自制循环（零成本、需时间）vs 订阅库休闲 loop（快、需预算/授权）——请拍板。
2. **连锁升调是否启用**：启用则需交付 `match_1`…`match_5` 并由程基岩接选档表；不启用则仅交付 `match` 基准音（行为同现状）。

4. **音量微调**：BGM 建议 `musicVolume` 0.5→0.4，SFX 峰值见 §2；如无异议按表落地。
