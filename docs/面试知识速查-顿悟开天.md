## 一、游戏性能（必考 — 试玩广告命门）

### 1.1 包体大小

**面试速答**：微信小游戏主包 ≤ 4MB，抖音 ≤ 2MB，海外 Facebook Instant ≤ 2MB。压缩手段五板斧：纹理压缩、音频压缩、代码 Tree Shaking、Bundle 分包、Bitmap Font 替代 TTF。

| 手段 | 具体做法 | 关键数字 |
|------|----------|----------|
| **纹理压缩** | PNG → JPG（无透明通道时）/ PNG8（256 色以内）/ ETC2（Android）/ ASTC（iOS+Android） | 一张 1024² PNG 约 1-3MB，ASTC 4x4 压到 ~256KB |
| **图集合并** | 多张散图 → 一张 SpriteAtlas，减少 draw call + 减少文件头开销 | 合并后 draw call 从 N → 1 |
| **音频压缩** | wav → mp3（128kbps）/ ogg（96kbps），删除多余声道，缩短时长 | wav 3MB → mp3 300KB |
| **代码压缩** | TS 编译开 minify、关闭 debug/assert、Tree Shaking 删未引用模块 | 体积减 30-50% |
| **Bundle 分包** | 核心玩法进主包，皮肤/关卡/音效走 Asset Bundle 按需加载 | 主包只保留 30 秒核心循环 |
| **字体** | TTF → Bitmap Font + 字符子集（只打包用到的字） | TTF 3MB → BMFont 50KB |

**你的项目映射**：「我的 BoardLogic.ts 是纯 TS 零 cc 依赖，Tree Shaking 友好；项目用了对象池减少运行时实例化开销。Bundle 分包和远程 CDN 在补，但'分层 + 按需加载'的思路是通用的。」

**Cocos Creator 构建配置**：
- Build 面板 → 勾选「压缩纹理」（选择 ETC2 + ASTC 平台组合）
- Build 面板 → 勾选「压缩脚本」（UglJS / Terser）
- Build 面板 → 「主包压缩类型」选 `subpackage` 或 `zip`
- `config` 文件里 `subpackages` 字段配置分包目录

### 1.2 运行效率（帧率）

**面试速答**：60fps = 每帧 16.67ms 预算。优化手段：图集合并减 draw call、节点复用减实例化、预分配 Vec3 减 GC、避免 update 里重计算、合批（Batching）。

| 手段 | 原理 | 代码示例 |
|------|------|----------|
| **图集合并** | 多张散图合成一张，GPU 一次绘制 | SpriteFrame 引用同一 SpriteAtlas |
| **Draw Call 优化** | 合批：相同材质 + 相同纹理 + 相邻渲染顺序 → 自动合批 | 静态合批、动态合批（`BatchingUtility.batch`） |
| **预分配 Vec3** | 避免 `new Vec3()` 在 update 里频繁触发 GC | `private _tmpPos = new Vec3();` 复用 |
| **减少节点数** | 每个节点有 Transformer + UIRenderer 开销 | 用 Graphics 画线代替 Line+Node 拼接 |
| **避免 update 重算** | update 里不做 `find()`、`GetComponent`、遍历查找 | 缓存引用，初始化时拿好 |
| **对象池** | 频繁创建/销毁的对象复用 | `nodePool.get()` / `nodePool.put()` |
| **遮挡剔除** | 不可见的节点 `active = false` | 比 `opacity = 0` 省 renderer 开销 |

**你的项目映射**：「Flappy 项目里 moveBg 用 `_tmpP1/_tmpP2` 预分配 Vec3 避免 GC；pipeSpawner 用对象池 pop/push 复用管道节点。三消用对象池复用方块。这三套是跨项目通用的帧率优化手段。」

**Cocos Creator 性能面板**：
- 编辑器 → 窗口 → 性能面板（Profiler）：看 DrawCall 数、FPS、内存
- 面板里重点关注：DrawCall > 50 需优化，FPS < 30 需优化，TriCount 过高需减面

### 1.3 内存占用

**面试速答**：对象池复用、资源用完 `decRef()` 释放、纹理及时回收、避免内存泄漏（闭包引用 + 事件未反注册）。

| 手段 | 具体做法 | 常见坑 |
|------|----------|--------|
| **对象池** | `NodePool` 或自建数组，pop/push 复用 | 池里对象要 `active = false` + 重置状态 |
| **资源释放** | `asset.decRef()` → 引用计数归零自动释放 | 只 `destroy()` 不 `decRef()` = 内存泄漏 |
| **Bundle 释放** | `assetManager.releaseBundle(name)` | 释放后引用到的资源会变无效 |
| **纹理回收** | 动态加载的纹理用完 `tex.decRef()` | 图集引用同一纹理，释放前确认全部不用 |
| **事件反注册** | `node.off('xxx', cb, this)` | `target` 不传 = 解绑所有，可能误删 |
| **闭包泄漏** | tween 的 `.call(() => {...})` 持有节点引用 | 动画结束后确保回调不持有已销毁节点 |
| **定时器清理** | `unschedule(callback)` / `unscheduleAllCallbacks()` | 节点销毁前清定时器 |

**内存管理三原则**：
1. **谁加载谁释放** — 加载资源的模块负责释放
2. **引用计数归零才回收** — 多处引用同一资源时，全部 decRef 后才真正释放
3. **池化 > 销毁 > 重建** — 能池化就不销毁，能销毁就不留着

**你的项目映射**：「三消项目用了对象池管理方块节点；动画用 tween + Promise 编排，动画结束后 `.call(() => resolve())` 不持有额外引用。decRef 我项目里还没用到（主包内静态资源），但在补。」

### 1.4 兼容性

**面试速答**：多平台适配靠 Widget 锚点 + 设计分辨率 + 屏幕安全区；API 兼容靠引擎版本统一 + 条件编译；降级策略针对低端机减少粒子/降低帧率。

| 维度 | 具体做法 |
|------|----------|
| **屏幕适配** | 设计分辨率（如 720×1280）+ `Canvas` 的 `Fit Width` / `Fit Height` + Widget 锚点 |
| **安全区** | iPhone 刘海屏 / 全面屏：`sys.getSafeAreaRect()` 获取安全区，UI 避让 |
| **API 兼容** | 不同平台 API 差异用 `sys.platform` 判断（`WECHAT_GAME` / `BYTEDANCE` / `DESKTOP_BROWSER`） |
| **性能降级** | 低端机检测（`sys.cpu` / 内存等级）→ 降低粒子数 / 关闭后处理 / 降帧到 30fps |
| **引擎版本** | Cocos Creator 版本统一，构建时选目标平台自动处理 polyfill |
| **微信小游戏特有** | 不支持 `eval` / `Function` 构造、不支持 `Image` 对象（用 `SpriteFrame` 代替）、域名白名单 |

**适配策略口诀**：宽适配（Fit Width）竖屏优先，高适配（Fit Height）横屏优先，Widget 钉四角保安全区。

**你的项目映射**：「三消项目用 Canvas + Widget 锚点做了竖屏适配，方块位置基于网格坐标计算不依赖绝对像素。屏幕适配这块我项目里是做的，多平台降级在补。」

## 二、游戏逻辑

### 2.1 状态机（Finite State Machine）

**面试速答**：用有限状态机管理游戏流程（菜单 → 游戏中 → 暂停 → 结算），每个状态有 enter/update/exit 三方法，状态间切换通过事件或条件触发。

```typescript
// 简单状态机
enum GameState { MENU, PLAYING, PAUSED, GAMEOVER }

class StateMachine {
    private current: GameState;
    enter(state: GameState) { /* 进入逻辑 */ }
    transition(to: GameState) {
        this.exit(this.current);
        this.current = to;
        this.enter(to);
    }
}
```

**你的项目映射**：「三消项目有 isProcessing 输入锁 + 死局检测 + restartBoard，本质就是一个简化状态机（空闲 → 处理中 → 空闲 / 死局 → 重开）。如果要正式做会抽成 StateMachine 类。」

### 2.2 事件系统 / 事件总线

**面试速答**：Cocos 有节点级事件 `node.on/emit` 和全局事件 `EventTarget`。解耦模块间通信用事件总线（EventTarget 实例），发布者 emit 事件名，订阅者 on 注册回调。

| 方式 | 适用场景 | 注意点 |
|------|----------|--------|
| `node.on('event', cb, this)` | 节点级通信（如按钮点击） | 节点销毁时自动解绑 |
| `EventTarget` 实例 | 全局/跨模块通信 | 需手动 `off` 解绑，否则泄漏 |
| `director.emit/on` | 全局引擎事件 | 不推荐业务用，和引擎事件混 |
| `input.on(TOUCH_START, cb)` | 全局输入 | 需在 `onDestroy` 里 `input.off` |

### 2.3 MVC / MVVM 架构

**面试速答**：MVC = Model（数据+逻辑，零引擎依赖）+ View（渲染+输入）+ Controller（流程调度）。好处是逻辑可测试、视图可替换、职责清晰。三消游戏的 Model 不引用 `cc` 模块，可以跑 Node 单测。

**你的项目映射**：「我的三消项目正在从扁平结构重构为 MVC — BoardLogic 是 Model 层基础，正在拆成 CellModel（per-cell 数据 + 命令队列）+ GameModel（状态封装 + 逻辑 + 动画指令生成），View 层抽 CellView + GridView，Controller 抽 GameController 管流程和分数。」

### 2.4 对象池（Object Pool）

**面试速答**：频繁创建/销毁的节点用对象池复用。`NodePool` 或自建数组，`get()` 取 `put()` 还，减少 GC 和实例化开销。

```typescript
// Cocos Creator 3.x 对象池
const pool = new NodePool();
// 存
pool.put(node);
// 取
const node = pool.get();
// 或自建
private pool: Node[] = [];
get(): Node { return this.pool.pop() ?? instantiate(this.prefab); }
put(node: Node) { node.active = false; this.pool.push(node); }
```

**你的项目映射**：「Flappy 的 pipeSpawner 和三消的方块管理都用了对象池，是 pop/push 模式。」

### 2.5 命令队列模式

**面试速答**：逻辑层一次性算完所有动画指令（cmd），推入队列，View 层统一消费用 `tween.delay(t).to(time).call()` 并行播放。比 async/await 串行快 N 倍。

```typescript
interface CellCommand {
    action: 'moveTo' | 'toDie';
    playTime: number;  // 延迟开始
    keepTime: number;  // 持续时间
    pos?: { row: number; col: number };
}
// View 消费
for (const cmd of model.cmdList) {
    tween(node).delay(cmd.playTime).to(cmd.keepTime, { position: ... }).start();
}
```

**你的项目映射**：「正在重构中，从 async/await 串行改为命令队列并行。参考项目 kaixinxiaoxiaole 就是这个模式。」

### 2.6 数据驱动设计

**面试速答**：关卡配置用 JSON/数据表驱动，代码只读配置不做硬编码。好处是策划改数值不用改代码，关卡扩展只需加数据。

```typescript
// 关卡配置 JSON
{ "level": 1, "targetScore": 1000, "moves": 20, "gridType": "7x6", "colors": 4 }
// 代码读取
const config = jsonassets.find(c => c.level === currentLevel);
```

## 三、UI 交互

### 3.1 Widget 锚点系统

**面试速答**：Widget 组件让节点相对于父节点边缘对齐（上下左右 + 宽高），是屏幕适配的核心。Canvas 根节点设设计分辨率，子节点用 Widget 钉住。

| Widget 属性 | 效果 |
|-------------|------|
| `top / bottom / left / right` | 距父节点边缘的距离 |
| `isAlignTop` 等 | 是否启用该方向对齐 |
| `alignMode` | ALWAYS（每帧）/ ONCE（仅一次）/ ON_WINDOW_RESIZE |

**面试常见追问**：「Widget 和 Layout 的区别？」— Widget 是锚点定位（钉到某个位置），Layout 是自动排列（子节点按规则排布）。两者可叠加：Layout 排列 + Widget 定位容器。

### 3.2 屏幕适配策略

**面试速答**：设计分辨率 + Fit Width/Height。竖屏游戏用 Fit Width（宽度撑满，高度裁剪），横屏用 Fit Height。UI 元素用 Widget 钉安全区。

| 适配模式 | 效果 | 适用场景 |
|----------|------|----------|
| `FIT_WIDTH` | 宽度撑满，高度多余裁剪 | 竖屏游戏 |
| `FIT_HEIGHT` | 高度撑满，宽度多余裁剪 | 横屏游戏 |
| `SHOW_ALL` | 全部显示，可能留黑边 | 不推荐（有黑边） |
| `NO_BORDER` | 无黑边，可能裁剪 | 和 FIT_WIDTH/HEIGHT 类似 |

**安全区适配**（iPhone 刘海屏）：
```typescript
const safeArea = sys.getSafeAreaRect();
// UI 元素 top 偏移 = 屏幕高度 - safeArea.yMax
```

### 3.3 触摸事件系统

**面试速答**：Cocos 3.x 用 `input` 全局事件 + 节点 `EventTouch`。触摸有 START → MOVE → END 三阶段，支持多点触控。

```typescript
// 方式一：节点级触摸
node.on(Node.EventType.TOUCH_START, (event: EventTouch) => {
    const uiPos = event.getUILocation();  // UI 坐标
    const worldPos = event.getLocation(); // 世界坐标
}, this);

// 方式二：全局触摸
input.on(Input.EventType.TOUCH_START, (event: EventTouch) => {
    const touches = event.getTouches(); // 多点触控
}, this);
```

**事件冒泡**：触摸事件从最上层节点开始向下传递，`event.propagationStopped = true` 可阻止冒泡。

**你的项目映射**：「三消项目用 `node.on(TOUCH_START)` 监听方块点击，点击后判断相邻关系决定选中或交换。」

### 3.4 UI 层级管理

**面试速答**：UI 层级用节点排序管理。弹出面板放到高层级节点，普通 UI 在低层级。常见做法是 Canvas 下分多层（Background / Game / UI / Popup / Loading）。

```
Canvas
├── Background     (z=-10)  背景层
├── GameLayer      (z=0)    游戏内容
├── UILayer        (z=10)   HUD/按钮
├── PopupLayer     (z=20)   弹窗
└── LoadingLayer   (z=30)   加载/转场
```

### 3.5 Layout 布局组件

**面试速答**：Layout 组件自动排列子节点（水平/垂直/网格），适合列表、按钮组、背包网格。不需要手动计算位置。

| 类型 | 排列方式 |
|------|----------|
| `HORIZONTAL` | 水平排列 |
| `VERTICAL` | 垂直排列 |
| `GRID` | 网格排列 |

**面试追问**：「Layout 和手动定位的性能差异？」— Layout 每帧重算子节点位置（`updateLayout`），子节点多时有开销。静态布局可手动定位 + `Layout.enabled = false`。

## 四、动画表现

### 4.1 tween 系统

**面试速答**：tween 是命令式链式补间动画，`tween(node).to(duration, props).call().start()`。适合动态参数动画（位置每次不同）。

| API | 作用 | 区别 |
|-----|------|------|
| `.to(dur, props)` | 在 dur 秒内**变化到**目标值（绝对值） | 终点固定 |
| `.by(dur, props)` | 在 dur 秒内**变化了**目标值（相对值） | 终点 = 当前 + 增量 |
| `.call(fn)` | 动画完成后回调 | 相当于 onComplete |
| `.delay(t)` | 延迟 t 秒 | 在链中插入等待 |
| `.easing(name)` | 缓动函数 | quadOut / cubicInOut / backOut 等 |
| `.start()` | 启动 tween | 不调用不执行 |
| `.union()` | 合并链为一个动画 | 减少内部 tween 实例 |
| `.repeat(n)` | 重复 n 次 | -1 = 无限循环 |
| `.sequence()` | 串行 | 依次播放 |
| `.parallel()` | 并行 | 同时播放 |

**面试必背口诀**：`to` = 去到（绝对值），`by` = 加上（相对值）。摩丰面试答反了，这次不能错。

```typescript
// to: 从当前位置移动到 (100, 200)
tween(node).to(0.3, { position: new Vec3(100, 200, 0) }).start();

// by: 从当前位置加上 (100, 200)
tween(node).by(0.3, { position: new Vec3(100, 200, 0) }).start();
// 如果当前在 (50, 50)，by 后到 (150, 250)
```

**你的项目映射**：「三消项目用了 tween 的 `.to()` 做移动/交换/消除动画，`.call(() => resolve())` 包 Promise 做时序控制，easing 用 `quadOut` 做下落缓动。」

### 4.2 Animation Clip（关键帧动画）

**面试速答**：Animation Clip 是数据驱动动画，编辑器可视化编辑关键帧。适合固定可复用的动画效果（如选中放大、爆炸特效）。运行时用 `animation.play('clipName')` 播放。

| 概念 | 说明 |
|------|------|
| AnimationClip | 动画资源（.anim 文件），包含轨道和关键帧 |
| AnimationTrack | 轨道，绑定节点属性（position / scale / color） |
| Keyframe | 关键帧，某个时间点的属性值 |
| Animation 组件 | 挂在节点上，管理多个 Clip 的播放 |
| wrapMode | 循环模式：Normal / Loop / PingPong / Reverse |
| AnimationClip.EventType | FINISHED / PAUSE / PLAY |

**tween vs Animation 对比**（面试高频）：

| 维度 | tween | Animation Clip |
|------|-------|----------------|
| 创建方式 | 代码命令式 | 编辑器可视化 |
| 参数动态性 | 运行时计算（灵活） | 固定值（可复用） |
| 适用场景 | 移动/交换（位置每次不同） | 选中/爆炸（效果固定） |
| 帧事件 | `.call()` 回调 | 编辑器事件帧（精确时间点） |
| 复用性 | 每次创建 | 一个 clip 多处播放 |

**你的项目映射**：「三消项目混合使用 — tween 处理移动/交换（位置动态），Animation Clip 处理消除放大（效果固定可复用）。block.prefab 挂了 Animation 组件引用 eliminate.anim。」

### 4.3 帧事件（Animation Event）

**面试速答**：在 Animation Clip 的时间轴上某一帧添加事件，播放到该帧时调用指定函数。帧事件只能调用与 Animation 组件**同节点**的组件方法。

| 方式 | 精度 | 适用场景 |
|------|------|----------|
| update 帧计数 | 帧级（16ms） | 粗粒度检测（如倒计时） |
| Animation 事件帧 | 帧级（精确到帧） | 动画中间触发（如第 3 帧播放音效） |
| tween `.call()` | 时间驱动（连续） | 动画结束后回调 |

**帧事件使用步骤**：
1. 编辑器选中 .anim 文件 → 时间轴上右键某帧 → 添加事件
2. 事件属性里填函数名（如 `onEliminateEnd`）
3. 在 Animation 组件同节点的脚本里定义该函数
4. 如果回调逻辑在其他节点 → 通过 `node.emit()` 中转

**你的项目映射**：「三消项目用帧事件做了消除动画结束回调 — eliminate.anim 第 0.15s 添加事件帧调用 BlockController.onEliminateEnd()，再 emit 事件给 GameManager。」

### 4.4 粒子系统

**面试速答**：ParticleSystem 组件做粒子特效（爆炸、烟雾、光效）。面试一般问参数调优和性能。

| 常用参数 | 说明 |
|----------|------|
| `duration` | 持续时间 |
| `startColor` | 起始颜色 |
| `startSize` | 起始大小 |
| `startSpeed` | 起始速度 |
| `emissionRate` | 每秒发射数（影响粒子总数） |
| `maxParticles` | 最大粒子数（影响性能） |

**性能注意**：粒子数 < 200 为安全线；低端机减半或关闭；用 `playOnAwake = false` 手动控制播放时机。

### 4.5 骨骼动画（Spine / DragonBones）

**面试速答**：角色动画用 Spine 或 DragonBones 骨骼动画。Cocos Creator 3.x 内置 `sp.Skeleton` 组件。

| 概念 | 说明 |
|------|------|
| Skeleton 组件 | 挂载 Spine 动画 |
| Animation Name | 动画名（idle / run / attack） |
| Skin | 换皮（同一动画不同贴图） |
| Loop | 是否循环 |
| Mix/Blend | 动画过渡（混合时间） |

**性能注意**：骨骼动画比逐帧动画省内存（一张贴图 + 骨骼数据），但 CPU 开销大（每帧计算骨骼矩阵）。同屏骨骼动画数量 < 10 为安全线。

## 五、资源加载

### 5.1 resources.load（主包内资源）

**面试速答**：`resources.load(path, type, callback)` 加载 `resources/` 目录下的资源。异步加载，可包 Promise。

```typescript
// callback 风格
resources.load('prefabs/block', Prefab, (err, prefab) => {
    if (err) return;
    const node = instantiate(prefab);
});

// Promise 封装
function loadAsync<T>(path: string, type: typeof Asset): Promise<T> {
    return new Promise((resolve, reject) => {
        resources.load(path, type, (err, asset) => {
            if (err) reject(err);
            else resolve(asset as T);
        });
    });
}

// 加载目录
resources.loadDir('textures', SpriteFrame, (err, assets) => { /* ... */ });
```

**面试追问**：「resources.load 和 instantiate 的区别？」— `resources.load` 加载的是资源（Prefab/Texture/AudioClip），`instantiate` 是从 Prefab 创建节点实例。load 一次可 instantiate 多次。

### 5.2 Asset Bundle（分包加载）

**面试速答**：Asset Bundle 是独立资源包，可按需加载/释放，突破主包 4MB 限制。`assetManager.loadBundle(url, cb)` 加载，加载后用 `bundle.load(path, type, cb)` 取资源。

```typescript
// 加载 Bundle
assetManager.loadBundle('levels', (err, bundle) => {
    // 从 Bundle 加载资源
    bundle.load('level_1', JsonAsset, (err, json) => {
        const levelData = json.json;
    });
});

// 加载远程 Bundle（CDN）
assetManager.loadBundle('https://cdn.example.com/remote', (err, bundle) => {
    // ...
});

// 释放 Bundle
assetManager.releaseBundle('levels');
```

| 场景 | 做法 |
|------|------|
| 微信小游戏主包 ≤ 4MB | 核心玩法进主包，扩展内容走 Bundle |
| 多关卡 | 每关一个 Bundle，打完释放 |
| 皮肤系统 | 皮肤走远程 CDN Bundle，按需下载 |
| 试玩广告 | 主包只放 30 秒核心循环，其余全走远程 |

**配置方式**：编辑器 → 资源管理器 → 右键文件夹 → 配置为 Bundle → 构建时自动生成独立包。

### 5.3 预加载策略

**面试速答**：在玩家无感知时提前加载下一阶段资源，避免卡顿。常用 `bundle.preload(path, type, cb)` 预加载。

```typescript
// 进入第一关时预加载第二关资源
bundle.preload('level_2', JsonAsset, (err) => {
    // 预加载完成，第二关可直接加载（无卡顿）
});

// 预加载整个目录
bundle.preloadDir('level_2_assets', (err) => { /* ... */ });
```

**预加载时机**：
- 加载页 / Logo 页预加载首场景
- 第一关游戏过程中预加载第二关
- 转场动画期间预加载下一场景

### 5.4 资源释放

**面试速答**：资源用完要 `decRef()` 释放引用计数。只 `destroy()` 不 `decRef()` = 内存泄漏。Bundle 整体释放用 `assetManager.releaseBundle()`。

```typescript
// 单个资源释放
const tex = texture2D;
tex.decRef();  // 引用计数 -1，归零时自动释放

// 节点销毁时释放其资源
onDestroy() {
    this.sprite.spriteFrame = null;  // 先断引用
    this.texture.decRef();           // 再释放
}
```

**引用计数原理**：
- 加载资源时 refCount = 1
- 多处引用同一资源时 refCount++
- `decRef()` 时 refCount--
- refCount 归零 → 引擎自动 `destroy()` 并释放 GPU 内存

**常见泄漏场景**：
1. 动态加载纹理赋给 Sprite，换图后旧纹理没 `decRef()`
2. tween `.call()` 闭包持有已销毁节点引用
3. 全局事件 `EventTarget.on()` 没 `off()`
4. `schedule()` 定时器没 `unschedule()`

### 5.5 资源依赖管理

**面试速答**：Cocos 自动管理资源依赖。加载 Prefab 时自动加载其引用的 Texture/Material/AnimationClip。释放时也自动处理依赖（所有引用者都 decRef 后才释放被依赖资源）。

**查看依赖**：编辑器 → 资源 → 右键 → 查看依赖关系。构建后 `config.json` 里有完整的依赖图。

## 六、面试高频追问汇总

### 6.1 「你的项目怎么优化的？」

**三句话答法**：
1. 「帧率：对象池复用节点 + 预分配 Vec3 避免 GC + 图集合并减 draw call」
2. 「内存：动画结束后清理回调引用 + 事件反注册 + 定时器清理」
3. 「包体：BoardLogic 纯 TS 零 cc 依赖 Tree Shaking 友好 + resources 只放必要资源」

### 6.2 「tween 和 Animation 怎么选？」

**标准答法**：「不是二选一，是混合使用。动态参数（位置每次不同）用 tween 代码控制；固定效果（选中放大、爆炸）用 Animation Clip 编辑器可视化编辑 + 帧事件精确回调。跟场景大小无关，跟参数动态性有关。」

### 6.3 「to 和 by 的区别？」

**一句话**：`to` = 去到（绝对值，终点固定），`by` = 加上（相对值，终点 = 当前 + 增量）。

### 6.4 「怎么在某一帧调用代码？」

**三层**：
1. `update(dt)` 里帧计数（粗粒度，16ms 精度）
2. Animation 事件帧（帧级，精确到某一帧）
3. tween `.call()` 回调（时间驱动，无帧概念，动画链中的某一步）

### 6.5 「试玩广告和普通小游戏开发有什么区别？」

| 维度 | 普通小游戏 | 试玩广告 |
|------|-----------|----------|
| 包体 | 主包 4MB + 分包 | 极限压缩，通常 2-3MB |
| 时长 | 完整游戏 | 30 秒核心循环 |
| 首屏 | 1-3 秒可接受 | 必须 < 1 秒（秒开） |
| 资源 | 本地为主 | 远程 CDN 为主 |
| 适配 | 微信/抖音 | 微信/抖音/海外 Meta/Google 多平台 |
| 核心 | 留存/付费 | 转化率（点击下载） |

### 6.6 「微信小游戏有什么限制？」

- 主包 ≤ 4MB（不含分包）
- 不支持 `eval()` / `new Function()`
- 不支持 `Image` 对象（用 `SpriteFrame` / `Texture2D`）
- 不支持 `XMLHttpRequest` 同步请求
- 不支持 `WebAudio` 直接用（用 `AudioSource` / `AudioPlayer`）
- 域名需配白名单（`request` / `uploadFile` / `downloadFile`）
- 不支持 `localStorage`（用 `sys.localStorage` 封装）
